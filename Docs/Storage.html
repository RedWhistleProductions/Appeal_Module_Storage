Storage Module

Appeal docsModule standardBasicAdvancedGlobals

Script functions provided by the Storage module. Prefix each call with Storage; arguments below are consumed in the listed order. Plugin support and behavior may vary.

Basic covers ordinary application and game operations. Advanced covers explicit setup, backend management, and tuning. This classification describes the current API; it does not certify that every backend yet provides the complete Basic-only game workflow required by the standard.

Editor workspaces

Storage Open_Memory Name selects a named, temporary SQLite database, creating it if needed. It has no backing file and is released by Close Name. Use a distinct name to keep editor work separate from an application connection. Storage Try_SQL SQL executes SQL on the selected database and returns an empty string on success or the SQLite error message on failure. It returns no query rows and does not throw for SQL errors or automatically roll back a transaction; callers own any transaction or savepoint they create. These are Advanced SQLite commands.

SQL schema setup

Storage Execute_SQL SQL:string is an Advanced SQLite command for executing schema and write statements on the selected database. Pass SQL as one quoted string. It returns no query rows; errors throw and roll back any active transaction. Existing Set/Get and Insert/Find still use the original records table. See database setup scripts and schemas.

Table fields

Get_Field Table Key_Column Key Field returns a field as text (empty for a missing row or NULL). Set_Field Table Key_Column Key Field Value inserts or updates a field using the specified unique key. Names are validated SQL identifiers; keys and values are bound parameters. These commands are Advanced SQLite table access; they do not change Set/Get behavior.

Level designs

Create_Level Name creates a table pair without resetting data. Save_Level Name Snapshot atomically saves World tile maps and entities. Load_Level Name returns a snapshot for World Import_Level. Tables and the catalog belong to the selected database. See level design storage.

Globals

This module does not publish script-visible globals in its current module bridge. Plugin internals and C++ variables are not Appeal globals.

Reference source: module interpreter. Required arguments are not optional defaults. Advanced setup may be performed by Appeal configuration before a Basic script runs.
